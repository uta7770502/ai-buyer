# AI BUYER — 商品選択後の自動運用仕様

## 最終目標
ユーザー操作は「商品を選ぶ → 販売決定」のみ。以降は Shopify と CJdropshipping の連携で自動処理する。実装完了・本番稼働を意味する文書ではない。

## 自動処理の順序
1. CJ商品ID・バリエーション・仕入価格・配送可能国・送料・在庫を取得。
2. 決済手数料、想定返品コスト、為替変動バッファを含めた利益を計算。最低利益条件を満たさない商品は登録しない。
3. 商品名・説明・画像を生成・検証し、Shopify商品をまず下書き登録。バリエーションとSKUをCJのIDに紐づける。
4. 公開前に価格・在庫・配送可能性を再確認し、条件を満たす場合のみ販売開始。
5. Shopifyの注文Webhookを署名検証して受信し、支払い確定済み・未キャンセル・未返金の注文だけ処理する。
6. 注文IDと明細IDで冪等性を保証し、重複発注を防ぐ。商品・バリエーション・配送先・送料・仕入価格を再照合する。
7. 条件を満たす注文のみCJ発注APIに送る。CJ側の支払手段が自動決済に対応し、明示的に有効化された場合だけ自動支払いを行う。
8. CJ注文ID・追跡番号・配送ステータスを保存し、Shopifyへ反映。配送通知はShopify側の通知設定に従う。
9. 欠品・利益割れ・住所不備・APIエラー・支払失敗・配送遅延・返品は例外キューへ。再試行は回数制限とバックオフを設ける。

## 本番稼働の必須条件
- Shopify Admin APIのアクセストークンはサーバー環境変数のみで保持。
- Shopify Webhook HMACを生のリクエストボディで検証。未検証イベントは処理しない。
- CJ認証情報はサーバーのみで保持。顧客住所などの個人情報はログに出さない。
- 注文状態・CJ発注ID・再試行回数・イベントIDを永続DBに記録（ブラウザlocalStorageのみは不可）。
- 自動発注の初期設定はOFF。サンドボックスまたは小額テスト注文で一連の動作を検証してからONにする。
- 自動発注ON時にも「注文当たり最大仕入額」「最低利益額/率」「1日最大仕入額」を設定し、超過時は保留。
- 返金・キャンセル・二重注文の競合、部分出荷、配送不能地域をテストする。
- ShopifyとCJのAPI仕様・利用可能な支払手段・注文権限を本番接続前に確認する。

## 次の実装順
1. Shopify接続診断（読み取り専用）と必要スコープ確認
2. 商品下書き登録・CJ SKU対応表
3. 注文Webhook受信・署名検証・永続化
4. 発注プレビュー（dry-run）と利益・在庫の再照合
5. CJ発注・支払連携（利用可能な方式の確認後）
6. 追跡同期・例外処理・運用ダッシュボード

## 成功基準
テスト商品選択後、Shopifyへの登録、テスト受注、CJ発注、支払、追跡反映、例外通知まで、手動介入なしで完走できること。テスト未完了の段階で「完全自動」と表示しない。
